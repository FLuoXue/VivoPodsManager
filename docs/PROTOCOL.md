# 协议实现依据

来源：Zhaoyi-ya/TWS-Pods-PC 的 `vivo/PROTOCOL.md`、`vivo_protocol.py`、`vivo_models.py`、`vivo_features.py`，读取日期 2026-09-11。来源文档个别历史注释互有冲突，本实现优先采用更正后的命令语义及独立型号 profile，不使用已被证伪的命令。

## 传输

- RFCOMM UUID：`00000837-d102-11e1-9b23-00025b00a5a5`，通过 Windows SDP 发现服务，不猜固定通道。
- RFCOMM 帧：`FF version flags length vendor(2,BE) command(2,BE) payload [XOR]`。
- flags bit0 为 XOR，bit1 为 16 位大端长度。本实现支持拆包、粘包、噪声前缀和坏校验后重新同步。
- GATT service/write/notify 分别是 `00001100/1101/1102-d102-11e1-9b23-00025b00a5a5`。
- GATT 写入使用 WriteWithoutResponse，载荷只有 `vendor command payload`，没有 GAIA 帧头。
- 握手必须收到 GAIA vendor `000A` 的 `8300` 且首字节为 0。连接成功不等于握手成功。

## 版本与型号

| 型号 | 控制版本 | 降噪设置后缀 | 降噪查询载荷 | 注册链 |
|---|---:|---|---|---|
| vivo / iQOO TWS Air3 Pro | 3 | 04 00 | 空 | 是 |
| vivo TWS 3e | 3 | 03 | 空 | 是 |
| vivo TWS 4 / HiFi | 家族默认 4 | 03 01 | 00 | 是 |
| TWS 5 及其余家族默认 | 4 | 03 01 | 00 | 否 |

iQOO Air3 Pro 沿用同系列 Air3 Pro 的参数；TWS 4 的版本沿用上游 `select_profile` 的家族默认，但按协议文档发送注册链。这些组合仍需相应真机验证。其余型号的能力表和实际命令支持不能等同。

握手、电量、注册链固定用 v4，与上表的控制版本分开。已配对但没有名称匹配的自定义改名设备目前需要恢复 vivo / iQOO TWS 前缀后扫描。

## 命令与状态

| 功能 | SET | QUERY / REPORT |
|---|---|---|
| 电量 | — | 0207 / 8207 |
| 当前降噪 | 0130 | 0230 / 8230 |
| 长按循环 | 0131 | 0231 / 8231，type=05 |
| 双击映射 | 0102 | 0202 / 8202 |
| 佩戴检测开关 | 0103 | 0203 / 8203 |
| 实时佩戴 | — | 020D / 820D |
| EQ | 0118 | 0218 / 8218 |
| 查找 | 0120 | ACK 8120 |
| 固件 / 型号 | — | 021C / 021B |
| 多连接列表 / 切换 | 014A | 0249 / 8249 |
| 双设备开关 | 014C | ACK 814C |
| 时间同步响应 | 0509 | 由耳机 8509 请求触发 |
| 空间音效（实验） | 0139 | 0239 / 8239 |
| 低延迟游戏（实验） | 0151 | 0251 / 8251 |

- 降噪字节固定 `0=降噪 / 1=关闭 / 2=通透`。`0131` 只配置长按，不切当前降噪；`010C` 不用于降噪切换。
- 电量回包 `[00,L,R,C,charging]`，大于 100 为未知并将该部件读数置灰。充电 bit0/1/2 为左/右/盒。
- 佩戴 bit0/1 表示左/右在盒，bit2/3 表示左/右佩戴。
- 固件二进制字段使用 payload[2]、[5]、[6]，合理性检查失败则保留十六进制。
- TWS 3e 双连常开，不查询 0249，也不提供 014C 控件。
- 014A 始终发送全部设备的 MAC + state；未选设备保留原状态，仅将原活动设备降为已连接。
- 014D 删除配对记录未暴露，避免将切换音源与删除配对混为一谈。
- 空间音效、低延迟游戏为来源中尚未全面实测的推断命令，需用户手动开启实验功能。

序列号字段、触摸按钮映射子命令以及更多 ANC 子档位尚未提供足够可靠的映射，当前不暴露对应控件。
